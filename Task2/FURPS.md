# FURPS+ таблица: онлайн-заявки на депозиты и кредиты (MVP)

- Звёздочкой отмечены дополнительные требования, которые показались мне важные, но которых не было в исходных данных
- Архитектурно-значимые требования (ASR) помечены **[ASR]**

| Код | Требования | Комментарий |
|-----|------------|-------------|
| F | Функциональные (Functionality) | |
| F1 | Сайт: список депозитов с актуальными ставками | Ставки берутся из одного места (см. F9) |
| F2 | Сайт: заявка на депозит от нового клиента (Ф. И. О. и телефон), заявка попадает в систему кол-центра **[ASR]** | Нужна интеграция сайта с системой кол-центра |
| F3 | Кол-центр: менеджер видит заявку, звонит клиенту и может предложить особые условия | |
| F4 | После звонка новый клиент приходит в отделение для идентификации, сотрудник находит его заявку **[ASR]** | Заявка должна быть видна и в кол-центре, и в АБС |
| F5 | Интернет-банк: список депозитов с актуальными и персональными ставками клиента | |
| F6 | Интернет-банк: заявка на депозит с указанием счёта и суммы | |
| F7 | Подтверждение заявки (депозит, кредит) СМС-кодом **[ASR]** | Делает команда банка, без доработки ядра интернет-банка подрядчиком |
| F8 | Менеджер бэк-офиса обрабатывает заявку на депозит и подтверждает условия в АБС | В MVP процесс остаётся ручным |
| F9 | Ставки по депозитам ведутся в АБС вместо XLS-файлов, с ними работают бэк-офис депозитов и бэк-офис кредитов **[ASR]** | Там же согласование ставки по заявке |
| F10 | СМС клиенту после подтверждения ставки и после открытия депозита **[ASR]** | |
| F11 | Сайт: предложение по кредиту со ставкой, полные условия хранятся в Кредитном конвейере | Сайт берёт условия из Кредитного конвейера |
| F12 | Сайт: заявка на кредит (Ф. И. О. и телефон); если клиент ввёл паспортные данные - сразу показать решение по кредиту **[ASR]** | Решение даёт система скоринга по данным БКИ |
| F13 | После заявки на кредит с сайта клиенту приходит СМС с приглашением в отделение | |
| F14 | В отделении менеджер продолжает работу с заявкой с сайта или создаёт новую в АБС **[ASR]** | Заявка с сайта должна быть доступна в отделении |
| F15 | Интернет-банк: список кредитов и предодобренное предложение | |
| F16 | Интернет-банк: заявка на кредит (счёт зачисления и данные заявки) с подтверждением СМС-кодом; при изменении ситуации клиента - повторный упрощённый скоринг | |
| F17 | СМС клиенту при изменении статуса заявки на кредит | |
| F18 * | Клиент видит статус своих заявок в интернет-банке | Меньше звонков в кол-центр с вопросом «что с моей заявкой» |
| F19 * | Согласие клиента на обработку персональных данных и на запрос в БКИ при подаче заявки | Без согласия клиента нельзя запрашивать его данные |
| F20 * | Защита формы заявки на сайте от спама и ботов | Иначе кол-центр будет тратить время на фейковые заявки |
| U | Удобство использования (Usability) | |
| U1 | Максимально удобный интерфейс для клиента | Минимум полей, понятные шаги |
| U2 | Дизайн по принятой в компании системе: привычные цвета и брендированные элементы | |
| U3 * | Сайт и интернет-банк удобно открываются с телефона | Молодые клиенты в основном пользуются смартфонами |
| U4 * | Интерфейс удобен для пожилых клиентов: крупный шрифт, хороший контраст | Сейчас это основная аудитория банка |
| U5 * | Понятные сообщения об ошибках и о статусе заявки | Клиент должен понимать, что заявка принята |
| R | Надёжность (Reliability) | |
| R1 | Все сервисы работают 24/7 с доступностью 99,9% **[ASR]** | |
| R2 | Интернет-банк продолжает работать и выдерживать нагрузку при сбое ЦОД **[ASR]** | Сейчас всё работает в одном ЦОД, резервный включается вручную |
| R3 | Интернет-банк не работает напрямую с API и базой АБС в новом процессе **[ASR]** | База АБС перегружена. Заявки лучше передавать через очередь (Kafka) |
| R4 * | Заявки не теряются и не дублируются при передаче между системами | Потерянная заявка - потерянный клиент, дубль - два открытых депозита |
| R5 * | Заявки принимаются, даже если АБС, Кредитный конвейер или кол-центр временно недоступны | Заявка ждёт в очереди и обрабатывается позже |
| R6 * | Можно повторно запросить СМС-код, если он не пришёл | Без СМС-кода клиент не сможет подать заявку |
| R7 * | Если БКИ или скоринг недоступны, заявка с сайта всё равно принимается, решение приходит позже по СМС | БКИ - внешняя система, банк не управляет её доступностью |
| P | Производительность (Performance) | |
| P1 | Отклик по всем операциям - миллисекунды **[ASR]** | |
| P2 | Справочные данные (в т. ч. при платежах) загружаются быстрее 1 секунды **[ASR]** | Можно кэшировать справочники и ставки на стороне интернет-банка |
| P3 | Горизонтальное масштабирование и распределение запросов между серверами, приложениями и ЦОД **[ASR]** | |
| P4 | Нагрузка от онлайн-каналов на АБС должна быть минимальной **[ASR]** | АБС масштабируется только вертикально |
| P5 | Не нагружать систему скоринга предрасчётами в рабочие часы **[ASR]** | Предодобренные предложения можно считать ночью |
| P6 | Заявки по предодобренным предложениям обрабатываются в тот же рабочий день **[ASR]** | Обмен АБС → Кредитный конвейер раз в сутки, поэтому заявки из интернет-банка нужно передавать в Кредитный конвейер напрямую |
| P7 * | Система выдерживает рост числа клиентов интернет-банка | Цель трансформации - привлечь новых клиентов |
| S | Поддерживаемость (Supportability) | |
| S1 | Использовать технологии, которые уже есть в банке (MS SQL, Oracle, .NET, Java, Python) **[ASR]** | |
| S2 | Новые технологии - только совместимые с текущими платформами и понятные сотрудникам банка | |
| S3 | Для очередей использовать Kafka **[ASR]** | Текущая платформа интернет-банка с Kafka несовместима |
| S4 | Вынести открытие депозитов из монолита интернет-банка в микросервисы **[ASR]** | Меньше зависимость от подрядчика, можно подключить Kafka |
| S5 | СМС-подтверждение делает команда банка, без доработки ядра подрядчиком **[ASR]** | |
| S6 | Документация для дальнейшего расширения системы | |
| S7 * | Описание API и сообщений между системами | Систем много, без описания интеграции сложно поддерживать |
| S8 * | Логирование и мониторинг всех сервисов | Чтобы быстро находить сбои и выполнять требование 99,9% |
| S9 * | Доработки системы кол-центра и Кредитного конвейера - через их штатные возможности расширения | Это платформы подрядчиков, другие доработки могут сломаться при обновлении |
| +R | Ограничения (Restrictions) | |
| RS1 | Новый клиент обязательно приходит в отделение для проверки документов | |
| RS2 | Шифрование трафика на сайте и в интернет-банке (HTTPS) **[ASR]** | Передаются персональные данные клиента |
| RS3 | Ядро интернет-банка обновляет только подрядчик | |
| RS4 | АБС масштабируется только вертикально, её база перегружена | |
| RS5 | Обмен АБС → Кредитный конвейер раз в сутки, ускорить нельзя | |
| RS6 | Для нового клиента скоринг возможен только по общим данным БКИ | |
| RS7 | Партнёрский кол-центр - внешняя компания, работает по скриптам от бизнеса | |
| RS8 * | Доступ к заявкам по ролям (кол-центр, партнёрский кол-центр, отделение, бэк-офис) | Заявки содержат персональные данные, а партнёрский кол-центр - внешняя компания |
